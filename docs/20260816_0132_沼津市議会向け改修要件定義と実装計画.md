## 0. サマリ

本家「みらい議会」は**国会（衆議院・参議院の二院制）**を前提に作られている。これを**沼津市議会（一院制・地方自治法ベース）**向けに作り替え、さらに沼津市議会の公開情報を自動で取り込む。

調査の結論は3点。

1. **Fork元（`team-mirai/mirai-gikai`）への誤操作リスクは実在する。** 本リポジトリは GitHub 上で fork として登録されており（`isFork: true`, parent = `team-mirai/mirai-gikai`）、かつ `gh` のデフォルトリポジトリが未設定である。この状態で `gh pr create` を実行すると **base が upstream（team-mirai）に向く**。最優先で塞ぐ。
2. **データソースは想定より圧倒的に良い。** 沼津市議会の議会中継システム（DiscussVision SMART）に**認証不要の公開 JSON API** が存在し、会議一覧・発言単位のプレイリスト・**会議録全文テキスト**・議員名簿・会派・全文検索が機械可読で取れる。加えて議案審議結果・議案本文・会派別賛否が規則的な URL の PDF で公開されている。
3. **法務は当初考えたほどのブロッカーではない。**（2026-08-16 に3を全面改訂）沼津市公式サイトは「無断使用・転載、二次利用を禁止」と表示しているが、**この表示は著作権法の権利制限規定を封じる効力を持たない**。議案番号・議決結果などは**事実**で著作物でなく、条例本文は**13条1号**で権利の目的とならず、会議録の LLM 解析は**30条の4（情報解析）**、AI が独自表現で書いた解説は原文の複製でも翻案でもない。**市の許諾を待たずに実装・公開できる。** ただし**議会での発言の扱い**（40条1項／2項の解釈が学説上割れている）だけは設計で回避する必要がある。詳細は [議会情報の二次利用に関する著作権法上の整理](./20260816_0215_議会情報の二次利用に関する著作権法上の整理.md)。

## 1. 制約: Fork元リポジトリへの操作を全面禁止する

### 1.1 なぜ危険か（現状）

```
$ gh repo view seiichi3141/numazugikai --json isFork,parent
{"isFork":true,"parent":{"name":"mirai-gikai","owner":{"login":"team-mirai"}}}

$ gh repo set-default --view
X No default remote repository has been set.
```

fork リポジトリで `gh pr create` を打つと、`gh` は base repo を対話的に尋ねるか **parent（team-mirai/mirai-gikai）を既定候補にする**。AGENTS.md は「実装完了後は確認を挟まずコミット→push→PR作成まで一気に進める」と定めているため、**エージェントが自動で upstream に PR を出す事故が起こりうる**。issue 作成（`gh issue create`）も同様に parent に向く。

### 1.2 必須ガード（Phase 0 で即実施）

| # | 対策 | コマンド／内容 |
| :-- | :-- | :-- |
| G1 | `gh` のデフォルトリポジトリを自リポジトリに固定 | `gh repo set-default seiichi3141/numazugikai` |
| G2 | git remote に upstream を**追加しない**。既に無いことを維持 | `git remote -v` が `origin` のみであることを CI で検証 |
| G3 | GitHub 側で fork 関係を切る（推奨） | リポジトリ Settings から **Leave fork network**（GitHub Support 申請）。または upstream を持たない新規リポジトリへ履歴ごと移送 |
| G4 | AGENTS.md に禁止事項として明文化 | 「`gh pr create` / `gh issue create` は必ず `--repo seiichi3141/numazugikai` を明示する」「`-R team-mirai/*` を含むコマンドは実行禁止」 |
| G5 | `.claude/settings.json` の permissions で upstream 宛コマンドを deny | `deny` に `Bash(gh * team-mirai/*)` 等を追加 |
| G6 | pre-push フック | push 先 URL が `seiichi3141/numazugikai` 以外なら abort |

> **G3 が本質的な対策**。G1/G4/G5/G6 は運用ガードであり、fork network に居る限り「うっかり」の余地は残る。fork 関係を切れば `gh pr create` は構造的に upstream へ向かなくなる。ただし fork を切ると upstream の更新取り込み（`git fetch upstream`）も手動になるため、**本家の改善を今後取り込むかどうか**が判断材料になる（→ 9章の残論点 Q1）。

### 1.3 ライセンス上の義務（fork を切っても残る）

本家は **AGPL-3.0**。fork して独自運営する場合、AGPL-3.0 第13条によりネットワーク経由の利用者に対しソースコードの提供義務がある。加えて `FORK_GUIDELINES.md` が AGPL 第7条(c)(d)(e) に基づく追加条件として以下を要求している。**これは fork 関係を切っても順守義務が残る。**

- サービス名: 「みらい議会＠沼津市」形式にする、または完全に独自名称にする
- チームみらいのロゴ・タイポグラフィを使わない
- ヒーロー画像・OGP 画像を差し替える
- primary カラーをそのまま使わない
- 本家との関係を明示する（本家由来である旨とライセンス）

## 2. 国会 と 沼津市議会 のドメイン差分

### 2.1 制度上の違い

| 観点 | 国会（本家の前提） | 沼津市議会（To-Be） |
| :-- | :-- | :-- |
| 院の構成 | 二院制（衆議院 HR / 参議院 HC） | **一院制**。`house_enum` と `originating_house` は概念ごと不要 |
| 会期 | 常会・臨時会・特別会（第◯回国会） | **定例会（年4回: 2月・6月・9月・11月）**＋臨時会。「第13回（令和8年6月）定例会」のように**通し番号＋月**で呼ぶ |
| 会期長 | 常会150日 | 25〜40日程度（例: 令和8年第13回は6/5〜6/29） |
| 議案の提出者 | 内閣提出（閣法）／議員立法 | **市長提出が大半**。ほかに議員提出（発議）、委員会提出、市民からの**請願・陳情** |
| 議案の種別 | 法律案・予算・条約・決議 等 | 地方自治法第96条に基づき **条例・予算・決算・契約・財産・人事（同意）・報告・意見書/決議・請願/陳情** |
| 審議フロー | 先議院 委員会→本会議 → 後議院 委員会→本会議 | **委員会付託 → 委員会審査結果 → 本会議議決** の1段階のみ |
| 議決の語彙 | 可決・否決・継続審議 | **可決・否決・同意（人事）・認定（決算）・採択/不採択（請願陳情）・継続審査・撤回** |
| 委員会 | 常任17＋特別 | **常任4**（総務経済 / 民生病院教育 / 建設水道危機管理 / 一般会計予算決算）＋議会運営委員会＋特別委員会 |
| 議員 | 衆465・参248、政党単位 | **定数28**（第25期: 2023年5月〜2027年4月）。**会派**単位が実質単位 |
| 会派 | 政党 | 志政会(8) / 沼津志帥会(6) / 市民クラブ(5) / 公明党(3) / 日本共産党沼津市議団(2) / 無所属(3)※令和8年6月時点 |
| 賛否の可視化 | 記名投票・党議拘束 | **ほぼ全会一致で可決**。賛否が分かれた議案のみ議会だよりに**会派別**で掲載。**議員個人単位の賛否は非公開** |
| 「チームみらいの賛否」 | `mirai_stances` テーブルで管理 | チームみらい所属議員は沼津市議会に不在。**概念を「会派別賛否」に置換する** |

### 3.2 S1: DiscussVision SMART API（最重要）

沼津市議会の議会中継システムに、JSONP/JSON で応答する公開 API が存在する。テナントIDは **`436`**。

- ベース URL: `https://smart.discussvision.net/dvsapi/`
- クライアント実装: `https://smart.discussvision.net/smart/tenant/js/rd_ab/dvs_api.js`
- テナントID定義: `https://smart.discussvision.net/smart/tenant/numazu/WebView/js/tenant.js`

| エンドポイント | パラメータ | 返却内容 |
| :-- | :-- | :-- |
| `yearlist` | `tenant_id` | 年度一覧（平成年代〜令和8年）。`{"label":"令和8年","value":2026}` |
| `councilrd/all` | `tenant_id`, `year`, `council_id`, `schedule_id` ほか | **会議 → 日程 → 発言** の3階層。`council_id` / `label`（令和8年第12回定例会）/ `schedules[].label`（02月06日 本会議）/ `playlist[].speaker` / `content`（発言の見出し）/ `movie_name1` |
| `minute/text` | `tenant_id`, `council_id`, `schedule_id`, `playlist_id` | **発言の全文テキスト**（`minute_text`）。話者は `○議長（梶 泰久）` 形式で埋め込まれる |
| `group/memberlist` | `tenant_id`, `type` | **会派 → 所属議員** の一覧（`speaker_id` 付き） |
| `speaker/list` | `tenant_id`, `search_index` | 議員の氏名・かな・会派・顔写真ファイル名 |
| `councilrd/search` | `tenant_id`, `keywords`, `logical_op`, `from`, `to`, `speaker_id` ほか | 全文検索。ヒット件数付き |
| `councilrd/live` | `tenant_id`, `council_id` | ライブ配信情報 |

動作確認済みの呼び出し例:

```bash
curl -s "https://smart.discussvision.net/dvsapi/yearlist?tenant_id=436"
curl -s "https://smart.discussvision.net/dvsapi/councilrd/all?tenant_id=436&year=2026"
curl -s "https://smart.discussvision.net/dvsapi/minute/text?tenant_id=436&council_id=64&schedule_id=1&playlist_id=2"
curl -s "https://smart.discussvision.net/dvsapi/group/memberlist?tenant_id=436&type=1"
```

**評価**: これ1本で「会議体・日程・議員・会派・発言・会議録全文」が揃う。本家が国会に対して持っていない粒度の情報が、市議会側では逆に機械可読で手に入る。**自動化の主軸に据える。**

**留意点**:
- 非公式 API であり、仕様変更の予告はない。スキーマ変化を検知して落ちる仕組み（Zod スキーマ + 失敗時アラート）が必要。
- レスポンスは JSONP 前提だが、素の GET でも JSON が返る。
- 公開 API とはいえ、**負荷をかけない**（1リクエスト/秒程度、User-Agent に連絡先を入れる、会期外は週次）。

### 3.5 S4: ぬまづ市議会だより（会派別賛否）

`dayori/index.htm` → `dayori/r08/252.htm` → `dayori/r08/pdf/252-{page}.pdf`（号数は通し番号、年度フォルダ配下）。

**「会派別 賛否が分かれた議案一覧」**という表が毎号掲載され、これが賛否データの唯一の公開ソース。実データ:

```
会派別 賛否が分かれた議案一覧    〇：賛成 ×：反対 除：除斥  （）内は人数
                              議決結果 志政会⑻ 沼津志帥会⑹ 市民クラブ⑸ 公明党⑶ 日本共産党沼津市議団⑵ 無所属⑶
議第4号 沼津市特別職の職員の給与に関する条例の一部改正  可決  〇  〇  〇  〇  ×  〇×⑵⑴
議第39号 令和８年度沼津市一般会計予算              可決  〇  〇  〇  〇  ×  〇×⑵⑴
認第8号 副市長選任の同意（𠮷澤勇一郎）             同意  〇  〇  〇  〇  ×  〇×⑵⑴
```

**重要な性質**:
- 掲載されるのは**賛否が分かれた議案のみ**。掲載がない議案は「全会一致で可決」と解釈できる（この推論をデータモデルに落とす）。
- 単位は**会派**。無所属は「〇×⑵⑴」のように人数内訳になる。
- **議員個人の賛否は公開されていない。** 個人単位の賛否可視化は本サービスでは実装できない（→ 9章 Q3）。
- レイアウトが複雑な PDF のため、**LLM による構造化抽出**が現実解（既存の AI Gateway 基盤を流用）。

### 3.7 法的論点: 二次利用の可否

これが意味すること:

| 行為 | 判断 |
| :-- | :-- |
| 議案番号・件名・議決結果・日付などの**事実**を掲載する | 事実そのものに著作権は及ばない。**低リスク**だが、PDF全体の組織的な複製は編集著作物性の議論が残る |
| 議案本文 PDF・会議録全文を**そのまま転載**する | **不可**。要許諾 |
| 会議録全文を LLM に食わせ、**AI が独自表現で要約・解説を生成**して掲載する | グレー。原文を保存・配信しない設計なら比較的安全だが、**要確認** |
| 議案本文 PDF を `knowledge_source` として **DB に保存**する（非公開・AIコンテキスト用途） | グレー。公衆送信はしないが複製にあたる。**要確認** |
| 沼津市のページへ**リンク**する | 問題なし（リンクポリシー上も明示的な禁止なし。`robots.txt` は `/saijyo/` のみ Disallow） |
| DiscussVision の会議録テキスト | 著作権は沼津市に帰属。上と同じ扱い |

**→ Phase 0 のアクション（技術作業より先）**

1. **沼津市議会事務局**に対し、議会情報の二次利用（非営利・市民向け解説サービス）についての利用許諾を照会する。
2. あわせて、**議案・議決結果のオープンデータ化（CC BY での公開）を要望**する。これが通れば全ての論点が解消し、他自治体への横展開の道も開ける。
3. 許諾が得られるまでの暫定方針として、**「原文は転載せず、事実データ＋自サービスの独自解説＋公式ページへのリンク」に限定**した設計にする（3.8）。

### 3.8 恒久的な設計方針

> **【2026-08-16 更新】** 「許諾が下りるまでの暫定設計」だったものを、**恒久的な設計方針**に格上げする。許諾の有無にかかわらずこの形が適法かつ安全であり、暫定扱いする理由がないため。詳細は [著作権整理](./20260816_0215_議会情報の二次利用に関する著作権法上の整理.md) 7章。

- 事実データ（議案番号・件名・議決結果・会派別賛否・会期・委員会付託）は取り込む。**出典として沼津市議会の該当ページ URL を必ず併記する。**
- 議案本文・条例本文は `knowledge_source` として保持してよい（13条1号／著作物性が乏しい）。
- **会議録全文は DB に保存しない。** 解析ジョブが実行時に DiscussVision API から取得し、LLM に投入したうえで、**抽出された論点・意見のみを永続化**する（30条の4 の枠内に収める）。
- **議員個人の発言だけを集めたページ・アーカイブは作らない**（40条1項ただし書きに抵触するため、解釈のいずれの立場でも不可）。
- 議会中継の映像は転載せず、公式の再生ページへリンクする。
- 議員の自宅住所・電話番号は取り込まない。
- 議会だより・議案 PDF は丸ごと再配布しない。文章を載せる場合は引用の要件（明瞭区別・主従関係・出所明示）を満たす。
- サイト全体に「本サービスは沼津市および沼津市議会の公式サービスではありません」というディスクレーマを常時表示する（本家の `bill-disclaimer.tsx` を流用）。
- 解説が AI 生成であること・人のレビューを経ていることを明示し、誤りの指摘窓口を設ける。

### 4.5 「全会一致」の表現

議会だよりには賛否が分かれた議案しか載らない。したがって:

- `faction_votes` にレコードがある議案 → **賛否が分かれた議案**として会派別の表を表示
- レコードがなく `status = passed`（かつ当該定例会の議会だよりが取り込み済み）→ **「全会一致で可決」**と表示
- 議会だより未発行の定例会 → **「賛否情報は未公開」**と表示（誤って全会一致と表示しない）

この3状態の判定は純粋関数として `packages/shared` または feature の `shared/utils/` に切り出し、テストを必須とする（AGENTS.md のルール）。

## 5. 自動取り込みパイプライン設計

### 5.1 実行基盤: 既存の Cloud Run Job に相乗りする

本家はトピック分析用に `worker/`（Cloud Run Job）＋ `packages/topic-analysis-core` ＋ Cloud Scheduler の実行基盤を持っており、`--mode=analyze|backfill` で分岐している。**この基盤をそのまま流用する**のが最短かつ設計思想に合う。

```
[Cloud Scheduler] ──(OAuth)──→ [Cloud Run Job: numazu-ingest-worker]
                                  tsx worker/src/main.ts --mode=ingest --source=<...>
[Admin 手動実行ボタン] ──→ [Admin API /api/ingest/run] ──(run.jobs.run)──┘
                                        │ Supabase Secret Key
                                        ▼
                               Supabase (council_sessions / bills /
                                         factions / council_members /
                                         faction_votes / speeches)
```

新規パッケージ **`packages/numazu-ingest`** を作り、`worker/` と `admin/` の両方から import する（`topic-analysis-core` と同じ構成）。

```
packages/numazu-ingest/src/
├── fetchers/          # 外部からの取得（HTTP）
│   ├── discussvision-client.ts     # S1: JSON API
│   ├── gian-pdf-fetcher.ts         # S2/S3: 議案審議結果・議案本文
│   ├── dayori-fetcher.ts           # S4: 議会だより
│   └── yotei-fetcher.ts            # S6: 会期予定
├── parsers/           # ★純粋関数。テスト必須
│   ├── parse-gian-result-pdf.ts    # pdftotext -layout 出力 → 議案レコード[]
│   ├── parse-yotei-html.ts         # 会期予定表 → セッション[]
│   ├── parse-bill-number.ts        # "議第58号" → {kind:'gi', number:58}
│   ├── normalize-wareki.ts         # "8.6.29" → 2026-06-29
│   ├── map-committee-name.ts       # "民生病院教育" → committee_id
│   └── map-decision.ts             # "可決" → bill_status
├── extractors/        # LLM による構造化抽出（DIでモック可能に）
│   ├── extract-faction-votes.ts    # S4: 議会だよりPDF → 会派別賛否
│   └── schemas.ts                  # Zod スキーマ
├── repositories/      # Supabase 書き込み（createAdminClient）
├── services/
│   ├── ingest-sessions.ts
│   ├── ingest-bills.ts
│   ├── ingest-members.ts
│   ├── ingest-speeches.ts
│   └── ingest-faction-votes.ts
└── ingest.ts          # エントリポイント（worker から呼ぶ）
```

**設計原則（AGENTS.md 準拠）**:
- `parsers/` は外部依存ゼロの**純粋関数**。実データを固定した fixture を用意し `*.test.ts` を必須とする。
- LLM クライアントは**インターフェース定義 + DI**。テストでは Fake 実装に差し替える。
- Supabase はローカルインスタンスに実接続して統合テストする（`tests/supabase/` に追加）。
- `enable row level security` のみでポリシーなし。

### 5.2 取り込みフローと冪等性

| 順序 | ジョブ | ソース | 頻度 | 冪等キー |
| :-- | :-- | :-- | :-- | :-- |
| 1 | `ingest-sessions` | S6 会期予定 HTML + S1 `councilrd/all` | 週次 | `slug` / `external_council_id` |
| 2 | `ingest-members` | S1 `group/memberlist` + `speaker/list` | 週次 | `external_speaker_id` |
| 3 | `ingest-bills` | S2 議案審議結果 PDF（+ S3 の URL 収集） | **会期中 日次 / 会期外 週次** | `(council_session_id, bill_number)` |
| 4 | `ingest-speeches` | S1 `councilrd/all` → `minute/text` | 会期中 日次 | `(council_id, schedule_id, playlist_id)` |
| 5 | `ingest-faction-votes` | S4 議会だより PDF（LLM抽出） | 議会だより発行後（四半期） | `(bill_id, faction_id)` |

- すべて **upsert**。`ingestion_sources.content_hash` で内容が変わっていなければ**スキップ**し、外部サイトへの負荷と LLM コストを抑える。
- 会期中/会期外の判定は `council_sessions` の `start_date`/`end_date` から算出する純粋関数に切り出す。
- 1リクエストごとに 1秒スリープ。`User-Agent` に連絡先 URL を含める。
- 失敗時は `ingestion_runs.status = failed` + 非0終了（Cloud Run Job のリトライに委ねる）。

### 5.3 「AI解説」生成との接続

本家は `bill_contents`（難易度別の議案解説）を持ち、admin から AI 生成・編集できる。取り込んだ議案に対して:

1. `ingest-bills` が新規議案を `publish_status='draft'` で作成（**自動公開しない**）
2. admin の議案一覧に「未解説」として並ぶ
3. 運営者が AI 生成をトリガし、解説を生成 → **人がレビュー**（`is_review_completed`）→ 公開

**自動公開しないことは意図的な設計判断**。市議会情報の誤読は市政への誤解に直結するため、人のレビューを必須のゲートに置く。

### 5.4 インタビュー機能の市政向け再設計

本家の中核機能（AIインタビュー → 意見抽出 → トピック分析）はそのまま活きるが、問いの設計は作り替える必要がある。

| 観点 | 国会版 | 沼津市議会版 |
| :-- | :-- | :-- |
| 回答者の役割（`interview_report_role_enum`） | subject_expert / work_related / daily_life_affected / general_citizen | **居住地区（大平・戸田・原・西浦…）**、市民/市内在勤・在学/市外 の別を追加検討 |
| 問いの粒度 | 「この法案についてどう思うか」 | 「**あなたの生活のどこに効くか**」。市議会議案は生活に直結するため具体的に聞ける |
| 論点 | 全国的な賛否構造 | **地区間の利害・受益と負担・優先順位**。トピック分析の階層構造がそのまま使える |
| 成果物の宛先 | 国会対策チーム | **沼津市議会の各会派・議員**。「市民の声レポート」として渡せる形にする |

`packages/shared/src/interview-prompts/` の3モード（loop / bulk / targeted）はそのまま使える。プロンプト本文の書き換えが主作業。

| C1 | 会議録全文を永続化しない | `speeches` に `minute_text` 列を作らない。取得結果は解析関数のスコープ内で完結させる |

## 8. 検証方法

| 対象 | 方法 |
| :-- | :-- |
| パーサ（`parsers/`） | 実 PDF/HTML から起こした fixture に対する Vitest 単体テスト。**令和8年6月定例会の `gian-0806.pdf` から議案19件・報告8件・人事12件が正しく抽出できること** |

| DB function | `tests/supabase/db-function/` に統合テスト（AGENTS.md の必須ルール） |
| 品質ゲート | `pnpm lint` / `typecheck` / `build` / `test` を push 前にローカル通過 |

## 9. 残論点（要意思決定）

| # | 論点 | 選択肢 | 推奨 |
| :-- | :-- | :-- | :-- |
| **Q1** | GitHub の fork 関係を切るか | (a) 切る（upstream 操作リスクが構造的に消える／本家の更新取り込みは手動） (b) 残してガードで対処 | **(a)**。「Fork元への操作を禁止」という要件を確実に満たせるのは (a) のみ。本家の更新は必要時に `git remote add upstream --no-tags` を一時的に張って cherry-pick すればよい |
| ~~**Q2**~~ | ~~沼津市の許諾が下りなかった場合~~ | **【2026-08-16 解消】** 3.8 の設計方針の範囲であれば許諾がなくても適法。論点として消滅した（[著作権整理](./20260816_0215_議会情報の二次利用に関する著作権法上の整理.md) 1章） | — |
| **Q3** | 議員個人の賛否を扱うか | 公開データが存在しない | **扱わない**。会派単位に留める。将来的に議会に対して個人別賛否の公開を要望する材料にはなる |
| ~~**Q4**~~ | ~~会議録全文を DB に保存するか~~ | **【2026-08-16 確定】保存しない。** 解析時に都度取得し、抽出結果のみ永続化する（3.8 / 著作権整理 7.3） | — |
| **Q5** | サービス名称 | 「みらい議会＠沼津市」／独自名称 | 独自名称のほうが FORK_GUIDELINES の制約が緩く、将来の他自治体展開もしやすい |
| **Q6** | 運営主体 | 個人／任意団体／法人 | 利用規約・プライバシーポリシー・市への照会の名義に必要。**P0-3 より先に決める** |
| **Q7** | 対象範囲 | 議案のみ／一般質問も含む | 一般質問（S5）は市民の関心が高く、DiscussVision API で取れる。**Phase 3 以降で追加**を推奨。ただし**「○○議員の質問一覧」という議員別アーカイブの形にはしない**（40条1項ただし書き。著作権整理 N1） |
| **Q8** | 他自治体への横展開 | 沼津専用／マルチテナント | DiscussVision SMART は多数の自治体が採用しているため、`tenant_id` を差し替えるだけで他市に展開できる余地が大きい。**Phase 1 のスキーマ設計時に自治体を跨げる形にしておく**と後が楽 |

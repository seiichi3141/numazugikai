# 議案サムネイルの方針と生成手順

作成日: 2026-09-02

## 方針

- 議案ごとの写真は用意しない。`bills.thumbnail_url` が空の議案には**分野タグに対応する生成イラスト**を表示する（`web/src/features/bills/shared/utils/bill-thumbnail.ts`）。
- 管理画面からのアップロード（`thumbnail_url`）は従来どおり有効で、あればタグより優先する。
- 画像は装飾扱いで `alt=""` にする。見出しとタグが同じ情報を読むため、二重に読ませない。
- 画像は `web/public/img/bill-thumbnails/` に置く（Storage の転送量を使わない）。差し替えるときは**ファイル名を変える**（`next.config.ts` の `minimumCacheTTL` で長くキャッシュするため）。
- タグは DB のラベルで突き合わせる。タグ名を変えたら対応表も直す（seed と一致することをテストで固定している）。

## 生成手順（codex CLI）

`codex exec` の `image_generation` を使う。`-i` は可変長引数なので、プロンプトは標準入力（`-`）で渡す。

```bash
# 1. 元写真（実写風）
cat > p-base.txt <<'P'
画像生成ツールを使って、次の写真風の画像を1枚だけ生成し、このディレクトリに base-<key>.png という名前で保存してください。生成後はファイルパスだけ報告してください。

内容: <題材> 実写の風景写真のように。人物・文字・看板の文字・ロゴは入れない。横長 3:2。
P
codex exec --skip-git-repo-check --sandbox workspace-write --enable image_generation -C "$PWD" - < p-base.txt

# 2. イラスト化（元写真を添付）
codex exec --skip-git-repo-check --sandbox workspace-write --enable image_generation -C "$PWD" -i base-<key>.png - < p-illust.txt
```

イラスト化のプロンプト（`p-illust.txt`）:

```
添付写真の風景を、横長 3:2 の1枚のイラストとして再構成してください。写真部分は残さず、全面をイラストにします。

温かいアイボリーの紙背景の上に、同じ風景を「建築コラージュ＋シルクスクリーン＋設計図」のように再構成してください。単純な幾何学イラストにはせず、写真から抽出した 〈写真ごとの要素〉 などを、半透明の色面、重なった矩形、細い製図線、部分的に残した写真の質感で表現します。

配色は深いブルー、ブルーグリーン、セージ、チャコールを中心にし、写真の特徴的な色を1か所だけアクセントとして残します。

文字・数字・記号・番号・年号・ロゴは一切入れないでください。国際的な建築事務所、現代美術展、上質な旅行雑誌のような、静謐で土地性のあるデザインにしてください。単純な山のロゴ、味気ないフラットイラスト、汎用的な風景、子ども向け、3D、サイバー表現、安価なテンプレート感は避けてください。
```

1枚あたり 1〜2 分、2〜4 万トークン程度。

## 変換

生成物は 1536×1024 の PNG（2〜4MB）。幅 1200px の WebP（品質 80）に落として配置する。

```python
from PIL import Image
im = Image.open("illust-<key>.png").convert("RGB")
im = im.resize((1200, 800), Image.LANCZOS)
im.save("web/public/img/bill-thumbnails/<key>.webp", "WEBP", quality=80, method=6)
```

## 表示箇所

トップの議案カード（`bill-card`）、一覧（`bill-search-card`）、コンパクトカード（`compact-bill-card`）、議案詳細ヒーロー（`bill-detail-header`）、インタビュー LP、回答一覧ページ。いずれも `BillThumbnail` コンポーネント経由。

## 検討したが採らなかった案

- 手動アップロード運用（本家方式）: 800 件超の権利処理済み写真を用意するのは非現実的。
- 議案ごとの AI 画像生成: 費用と、市政情報に不適切な画像が混ざるリスク。
- `tags` テーブルに画像列を持たせる: 6 件の seed 管理のタグに対してマイグレーション・管理画面・アップロード導線が増える。タグが seed 外で管理されるようになったら再検討。

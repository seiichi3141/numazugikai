# 議案サムネイルの題材別画像と LLM による割り当て

作成日: 2026-09-02（前版: `20260902_1500_議案サムネイルの方針と生成手順.md`）

## 前版からの変更

前版は分野タグ 6 種の風景画像（富士山・港など）をタグから当てていた。次の2点を変えた。

- **議案の内容に合わせる**: 題材を 28 種に増やし、議案ごとに LLM が最も近い題材を選んで `bills.thumbnail_key` に保存する。
- **概念的な画像にする**: 人物（顔・手・シルエット）と実在の場所・建物を描かず、物や図面のモチーフだけで構成する。人事や賠償のような議案を「場面」で描くと誤解や不快感につながるため。配色はサイトの `--primary: #1b6ca8` / `--primary-accent: #14507c` と生成り `#f7f4f0` に揃えた。

## 仕組み

```
取り込み → 解説生成（--mode=explain）→ 題材の割り当て（explain の末尾で解説済み分を自動処理）→ bills.thumbnail_key
                                                                          ↓
                web: thumbnail_url → thumbnail_key → タグの既定題材 → general の順に画像を決める
```

- 題材の定義（key・名前・当てはまる議案の説明）は `packages/shared/src/bill-thumbnail/subjects.ts` にあり、割り当て側（`packages/bill-explainer`）と表示側（`web`）が同じ定義を読む。
- 割り当ては `@mirai-gikai/bill-explainer/assign-thumbnail-keys` の `runAssignThumbnailKeys`。解説と同じモデルに題材一覧と議案の正式名称・分類・タイトル・要約を渡し、key を1つ返させる（構造化出力で候補を限定し、保存前にもう一度一覧と突き合わせる）。
- worker: `--mode=thumbnail-keys`（未設定の議案すべて）、`--session=<slug>`、`--force`、`--limit=<n>`。`--mode=explain` の末尾でも、解説を生成できた議案だけを対象に決め直す（要約が変わるため）。
- 一覧 RPC（`bills_list_rows` / `search_bills_for_list`）は戻り値に `thumbnail_key` を含む（マイグレーション `20260902160000_add_bills_thumbnail_key.sql`）。
- 管理画面からアップロードした `thumbnail_url` は従来どおり最優先。

## 画像の生成手順

codex CLI の `image_generation` で、元写真を使わずに直接生成する。1枚 1〜2 分。同時実行は 6 でモデル側の混雑エラーが出ることがあるので、失敗分は 2 並列で再実行する。

```bash
codex exec --skip-git-repo-check --sandbox workspace-write --enable image_generation -C "$PWD" - < p-<key>.txt
```

プロンプト（`p-<key>.txt`。`<題材>` と `<モチーフ>` は上の表の値）:

```
「予算・決算・補正予算」という市議会の議案の分野を表す、横長 3:2 の概念的なイラストを作ってください。

構成: 温かい生成りの紙（#f7f4f0）を背景に、帳簿の罫線、積み上がった硬貨のシルエット、折れ線グラフの製図線、電卓、庁舎の窓のパターン。これらのモチーフを「建築コラージュ＋シルクスクリーン＋設計図」のように再構成します。半透明の色面、重なった矩形、細い製図線、部分的に残した写真の質感で表現し、静物のようにモチーフを画面中央付近にまとめて配置してください。

配色: 深い青（#14507c）と青（#1b6ca8）を主色に、セージとチャコールを補助色として使い、アクセント色は1か所だけ。

禁止: 人物（顔・手・シルエットを含む）、実在の建物や風景、地名や看板、文字・数字・記号・ロゴ、3D 表現、味気ないフラットイラスト、安価なテンプレート感。

国際的な建築事務所や現代美術展のような、静謐で品位のあるデザインにしてください。
```

生成物（1536×1024 PNG）は幅 1200px・品質 80 の WebP に変換し、`web/public/img/bill-thumbnails/<key>.webp` に置く。差し替えるときはファイル名を変える（`next.config.ts` の `minimumCacheTTL` が長いため）。

## 題材を足すとき

1. `subjects.ts` に key・label・description を追加する
2. 同じ key で画像を生成して `web/public/img/bill-thumbnails/` に置く（存在しないとテストが落ちる）
3. 必要なら `--mode=thumbnail-keys --force` で決め直す

## 本番への反映

1. マイグレーションは `main` への push で自動適用される（`deploy.yml`）
2. `thumbnail_key` の値はローカルで割り当てた結果を SQL にして本番へ流す（LLM を二度呼ばない）。手順は公開手順書の「データ複製」と同じく `psql "$SUPABASE_DB_URL"`
3. 反映後に `POST /api/revalidate` でキャッシュを切る

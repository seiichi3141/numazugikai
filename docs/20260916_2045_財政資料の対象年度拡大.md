# 財政資料の対象年度拡大（令和2〜8年度）

## 目的

`/finance` で令和8年度（予算）と令和6年度（決算）だけを表示していた状態を、
沼津市が公開している過去年度の公式PDFまで広げる。データ契約と公開フローは
[財政データ契約](20260904_1200_fiscal-data-contract.md)のまま変更しない。

## 対象資料

同じ様式の資料は年度ごとのディレクトリで公開されているため、様式（`parserKind`）は
共有し、年度とURLだけをprofileで分ける。年度は「年度が始まる西暦年」で持つ。

| 系列（`seriesCode`） | 資料 | 対象年度 | 公式URLの形 |
| :-- | :-- | :-- | :-- |
| `budget-overview-general-account` | 予算概要（一般会計） | 2023〜2026 | `yosan{2023..2026}/gaiyousho/pdf/s-1.pdf` |
| `budget-overview-council-expense` | 予算概要（議会費） | 2023〜2026 | `yosan{2023..2026}/gaiyousho/pdf/i-1.pdf` |
| `settlement-overview` | 決算の概要 | 2020〜2024 | `kessan{2020..2024}/pdf/gaiyou.pdf` |
| `major-measures-fiscal` | 市政報告書 第1章 財政 | 2020〜2024 | `kessan{2020..2024}/pdf_houkoku/1.pdf` |

- 令和4年度以前の予算概要と、令和7年度の決算概要・市政報告書は未公開のため
  profileを追加しない。公開された時点で同じ形式で足す。
- 令和6年度の市政報告書だけが既存profileで表題を「主要な施策の成果等報告書」と
  している。stagingの差分適用は`new` / `unchanged`のみ対応のため、既存profileの
  表題は変更しない（表題の統一は差分適用の対応後に扱う）。
- profileKey・URL・parserNameは年度ごとに一意にし、`fiscalSourceProfiles`の件数は
  18件になる。`--target=fiscal`の取込は全profileを対象にする。

`parserVersion`は「どの実装で解析したか」の記録ではなく、`prepareFiscalSource`が
完了済み解析を再利用してよいかを判定するprofile単位の再解析キーである。同じ
`parserKind`は同じ実装で解析するため、版は`PARSER_VERSIONS`で様式ごとに1つだけ持つ。
抽出結果が変わる改修をしたときは、その様式の版を上げて対象年度を再解析させる。

## parserの年度対応

年度印字のない資料はprofileの年度を正本とし、年度印字のある資料はprofile年度と
本文の年度が一致しなければhard errorにして静かに誤読しない。

- 予算概要（一般会計・議会費）: 年度を引数化。文字化け対策として、令和6年度PDFで
  発生する数字・記号の誤写像（CJK統合漢字拡張A、U+3ECC〜U+3EE5）を解析前に
  ASCIIへ戻す`normalizeMisencodedPdfAscii`を通す。増減率の桁区切り（`88,450.0`）、
  議会費の区分行と注記の同一行連結、費目名に数字を含む費目（市議会100周年記念事業費）
  も年度差として吸収する。
- 決算概要: 令和2・3年度は金額が款名より前に印字され、令和5年度の歳入は
  「902 億 8,042 万円」と千円の位を持たない。概要欄の終端は年度で並びが崩れる
  「（１）」の番号だけで判定し、金額は概要欄の2件を歳入・歳出の順に採用する。
- 市政報告書: 年度見出しは全角数字と字間の空白を含む年度があるため、NFKC正規化と
  空白除去の両方を行って照合する。

数字・記号の誤写像補正は全fiscal資料に一律で通す。実PDFでは令和6年度の
一般会計・議会費だけに出現し、他の年度では変換対象がなく素通りすることを確認した。
範囲がCJK統合漢字拡張Aと重なるため、将来の資料で本文の文字を書き換える可能性は
残るが、その場合は款名の照合や合計の検算が一致せずhard errorになる。

## 検証

- 実PDFから抽出したテキストで、一般会計38件・議会費1件・決算概要2件・市政報告書42件を
  全年度hard errorなしで抽出できることを確認した。
- fixtureは令和6年度一般会計（誤写像）、令和5年度議会費（事業費2費目）、
  令和2・5年度決算概要（印字順と単位の差）を追加し、年度ごとの様式差を回帰テストにする。

## 残作業

1. `apply_verified_fiscal_staging`はバッチ内に一次根拠（`evidenceRole=primary`）の
   金額が1件以上あることを要求する。議会費詳細と決算概要は比較用の`corroborating`
   だけを出すため、これらのバッチは単独では公開正本へ反映できない。決算の歳入決算額は
   一次根拠を持つ資料（決算書本体など）を追加するか、corroboratingのみのバッチを
   公開済み金額へ突き合わせる適用ワークフローを後続で用意する。
2. 決算概要の`corroborating`は千円未満を丸めた比較用の値である。年度別ページで
   歳入決算額を出すには1の対応が要る。現状の`/finance`は令和2〜6年度の決算として
   市政報告書の歳出決算額だけを表示する。
3. 当初予算の`decisionStage`は契約どおり`proposed`で保持するため、令和7・8年度は
   `/finance`で「まだ議会で議決されていません」と表示される。令和2〜6年度は
   市政報告書の`passed`が優先されるため議決済みとして表示される。令和7・8年度も
   含めて可決として表示するには、議決日を根拠に`passed`へ確定する後続工程が要る。

## ローカル取込の結果

ローカルのSupabaseで`--target=fiscal`を実行して確認した。18資料すべてが取得・解析され、
hard errorは0件、新規バッチは14件（令和8年度の一般会計・議会費、令和6年度の
市政報告書・決算概要は解析済みの版を再利用）。
検証した15バッチのうち7件を公開正本へ反映し、`/finance`と年度別ページで
令和2〜8年度の予算・決算が表示されることを確認した。

- 反映済み: 一般会計予算の令和5・6・7年度、市政報告書の令和2〜5年度
- 未反映: 議会費詳細と決算概要の計8バッチ（上記1の理由）
- 令和6年度の市政報告書と令和8年度の予算概要は反映済みの状態を再利用した

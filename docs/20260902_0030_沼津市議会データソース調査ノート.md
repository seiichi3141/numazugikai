# 沼津市議会 データソース調査ノート

- 作成日: 2026-09-02
- 関連: [20260816_0132_沼津市議会向け改修要件定義と実装計画.md](./20260816_0132_沼津市議会向け改修要件定義と実装計画.md) 3章

沼津市議会の公開情報をどこから、どこまで取れるのか。実際に叩いて確かめた結果を残す。
同じ調査を繰り返さないための記録であり、**推測ではなく検証済みの事実だけ**を書く。

## 情報源は3系統

| 系統 | 何が取れるか | 取得方法 |
| :-- | :-- | :-- |
| 市サイトのPDF | 議案名・分類・付託委員会・議決結果 | HTTP + `pdftotext -layout` |
| 議会中継（DiscussVision SMART） | 本会議の会議録・議員名簿・会派 | 公開JSON API |
| 会議記録検索システム（AmiVoice） | 本会議・委員会の会議記録 | HTML（POSTフォーム） |

## 1. 市サイトのPDF（議案の骨格）

**最も古くまで遡れる。平成16年（2004年）から。**

- 索引: `.../annai/houkoku/index.htm` → 期ごとの `teirei_{20..25}.htm`
- PDF: `teirei_{期}_pdf/gian-{元号年2桁}{月2桁}.pdf`
- 全6期・104会期分が公開されている

### 元号の落とし穴

ファイル名に元号が入っていない。平成16年6月も令和8年6月も `gian-1606.pdf` /
`gian-0806.pdf` の形になる。**URLから元号を推測してはいけない。**
PDF本文の見出し（「第5回（平成16年6月）定例会」）に書かれた元号で判定する。

### 議案本文PDFは開会中の会期のみ

`annai/oshirase.htm` に載る議案本文（`gian{YYMM}/gi-{n}.pdf`）は、
会期が終わると消える。過去分は取得できない（検証済み: 令和8年2月・令和6年11月とも404）。

## 2. 議会中継 DiscussVision SMART（本会議の会議録）

- ベース: `https://smart.discussvision.net/dvsapi/`
- テナントID: **436**（`/smart/tenant/numazu/WebView/js/tenant.js` に記載）
- 認証不要

| エンドポイント | 内容 |
| :-- | :-- |
| `yearlist` | 年度一覧 |
| `councilrd/all?year=` | 会議 → 日程 → 発言の3階層 |
| `minute/text` | 発言の全文 |
| `group/memberlist` / `speaker/list` | 会派・議員 |

### 取得可能な範囲は2022年以降

`yearlist` は平成年代も返すが、**会議録テキストが実際に取れるのは2022年から**。
それ以前は `councilrd/all` に会議が無い。

### 直近の会期は未整備

会議録の作成には数ヶ月かかる。令和8年6月定例会は取り込み時点で
`minute/text` が `error_code 2004` を返した（後日公開された）。
**議会中継とAmiVoiceは公開時期が逆**で、互いを補完する。

### 会派の人数を鵜呑みにしない

`group/memberlist` は**過去に登壇した議員をすべて含む**。
そのまま人数にすると志政会13人（実際は8人）のような誤情報になる。
現員数はこのAPIから決めないこと。

## 3. 会議記録検索システム AmiVoice（委員会の会議記録）

- ベース: `https://ami-search.amivoice.com/numazu/usr/search.exe`
- 個人情報保護のため発言の一部を伏せた「会議記録」で、正式な「会議録」とは異なる

### トップページに見えるのは直近だけ

`process=list_vcsm` は直近3会期＋委員会の固定コード（`---0`〜`---9`）しか返さない。
**しかし過去のアーカイブは存在する**（`m20230119_01.vcsm` を直接叩くと令和5年第16回が7会議分取れた）。

### 詳細検索で過去に辿れる（重要）

`process=detail` のフォームから検索する。**年の選択肢は1990年からある。**

```
POST search.exe
  process=search_detail
  word_and=<検索語>          ← 必須。空だと0件
  word_or=
  sch_type=001|002|003|004   ← 定例会/臨時会/全員協議会/その他（委員会は004）
  sch_mean=001
  sch_prt=003                ← 検索対象部分（003=本文）
  year1,month1,day1 / year2,month2,day2   ← 0,0,0 で全期間
```

結果ページからは `DataSubmit2('v{YYYYMMDD}_{NN}.vcsv', ...)` の形で
会議記録IDが取れる。本文は次で読める。

```
GET search.exe?process=disp_right&vcsv={ID}.vcsv&spk_id=&hits=&all_hits=
```

`<div class="sub2">` に `<b>○発言者</b>` と本文が入っている。

### 全件取れる。1990年から1787件

**検索パラメータが2つ不足していると、結果が激減する。** ここを間違えて
「古い年は文教産業委員会しか無い」と誤結論を出しかけた。正しくは全委員会・
1990年10月から2026年6月まで、**1787件すべて取得できる**。

#### 落とし穴1: `sch_mean` は全10種を送る

会議体の種類にあたるパラメータ。画面では委員会ごとのチェックボックスで、
既定では全部にチェックが入っている。ひとつ（`001`）しか送らないと
文教産業委員会に偏り、他の常任委員会が丸ごと落ちる。

| 送る値 | 2019〜2021年のヒット |
| :-- | :-- |
| `sch_mean=001` のみ | **32件**（ほぼ文教産業委員会） |
| `sch_mean` 全10種 | **365件**（全委員会） |

```
sch_mean=001&sch_mean=002&sch_mean=003&sch_mean=004&sch_mean=005
&sch_mean=006&sch_mean=007&sch_mean=008&sch_mean=009&sch_mean=000
```

#### 落とし穴2: 検索語は空にする

`word_and` に語を入れると、その語を含む記録だけに絞られる。
網羅したいときは空文字で送る（2019年で 7件 → 10件 の差が出た）。

#### 落とし穴3: 結果は1ページ30件。ページングが要る

「次の30件」ボタンは `fnSort(cur_id, 0)` で、`process=search_detail` に
`cur_id`（0, 30, 60, …）を付けて同じフォームを再送する。
ページに `btn_next30` があるかで継続を判定する。

### 動く検索リクエスト（検証済み）

```
POST search.exe
  process=search_detail
  word_and=              ← 空。語を入れると絞られる
  word_or=
  sch_type=001..004      ← 定例会/臨時会/全員協議会/その他
  sch_mean=001..009,000  ← 全10種。ここが最重要
  sch_prt=003            ← 本文
  sch_spk=0  sch_exc=0
  year1,month1,day1 / year2,month2,day2
  cur_id=0               ← 30ずつ増やしてページング
  srt_change=0
```

### 取得できる範囲（実測）

- 期間: **1990-10-04 〜 2026-06-29**
- 総数: **1787件**
- 会議体: 議会運営304 / 一般会計予算決算128 / 建設水道108 / 民生病院101 /
  総務89 / 特別会計企業会計予算決算87 / 文教産業83 / 総務経済20 /
  建設水道危機管理11 / 民生病院教育11 ほか

本会議（定例会・臨時会）も `sch_type=001,002` で取れる。
当初「本会議は検索経由では取れない」と書いたのも `sch_mean` 不足による誤りだった。

## 実装への反映

現在の取り込み（`@mirai-gikai/numazu-ingest`）は次の方針。

- 議案の骨格 → PDF。`--target=bills --term=NN` / `--all-terms` で期単位に取り込む
- 本会議の会議録 → 議会中継API。`--target=minutes --era-year=N`
- 委員会の会議記録 → AmiVoiceのトップページ経由。`--target=amivoice`
- 説明は**長い方を採用**する（`updateBillExplanationIfLonger`）。
  委員会の課長説明の方が本会議より具体的なため、自動的にそちらが残る

### 材料の実績（2026-09-02 時点・1147議案）

| 年 | 議案 | 説明の材料 | うち議会中継 | うちAmiVoice |
| :-- | :-- | :-- | :-- | :-- |
| 2019〜2021 | 432 | 0 | 0 | 0 |
| 2022 | 135 | 113 | 113 | 0 |
| 2023 | 138 | 102 | 102 | 0 |
| 2024 | 162 | 134 | 134 | 0 |
| 2025 | 148 | 127 | 98 | 29 |
| 2026 | 131 | 99 | 39 | 60 |

**2019〜2021年は解説の材料が無い。** 議会中継が2022年からで、
AmiVoiceの検索も全件を返さないため。議案名・分類・議決結果までは分かる。

## 次に試すこと

AmiVoiceから過去の委員会記録を網羅的に取るには、次のいずれかが要る。

1. ~~**会議記録IDの総当たり**~~ — **検証したが断念した。**
   IDは `v{YYYYMMDD}_{NN}` の形で、開催日さえ分かれば当てられる。
   しかし過去の期には会期日程PDF（`nittei-{YYMM}.pdf`）が存在せず
   （第24期のPDFは `gian-` と `ippan-` のみ）、委員会の開催日を特定する手段がない。
   議案審議結果PDFからは付託委員会と議決日は分かるが、**委員会の開催日は分からない**。
   日付を特定せずに総当たりすると、1年あたり365日×複数連番のアクセスになり、
   自治体サイトへの負荷として許容できない。
2. **市議会事務局への照会** — 検索の仕様と、過去記録へのアクセス方法を尋ねる。
   あわせて議会データのオープンデータ化（CC BY）を要望する
   （[著作権整理](./20260816_0215_議会情報の二次利用に関する著作権法上の整理.md) 8章）

1 を試す場合も、robots.txt（`/saijyo/` のみ Disallow）とアクセス間隔（1秒以上）を守ること。

## 相手サイトへの配慮

- `robots.txt` は市サイト・AmiVoice とも議会ページの取得を禁じていない
- リクエスト間隔は1秒以上あける（`NumazuSiteClient` / `AmivoiceClient` の `minIntervalMs`）
- User-Agent に連絡先URLを入れる
- 内容ハッシュ（`ingestion_sources.content_hash`）が同じなら再解析しない
